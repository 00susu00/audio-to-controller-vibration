# 性能优化指南

## 延迟优化

程序已经进行了大量优化以最小化延迟：

### 默认优化设置

1. **音频块大小**: 从4096减小到1024样本
   - 延迟从~93ms降低到~23ms (44.1kHz采样率)
   - 可进一步减小到512 (11ms) 或256 (6ms)，但会增加CPU负载

2. **缓冲区优化**:
   - 音频队列: 3个块 (原10个)
   - 音量分析窗口: 3个样本 (原10个)
   - GUI数据缓冲: 100个点 (原200个)

3. **处理频率优化**:
   - 音频处理: 移除固定延迟，最大化处理速度
   - GUI更新: 30Hz数字显示 + 15Hz图表更新
   - 监控检查: 60Hz (原10Hz)

### 进一步降低延迟的方法

#### 1. 命令行参数调整

```bash
# 极低延迟模式 (高CPU使用)
python main.py --chunk-size 256

# 平衡模式 (推荐)
python main.py --chunk-size 512

# 低延迟模式
python main.py --chunk-size 1024
```

#### 2. 音频设备优化

- 使用ASIO驱动的专业音频接口
- 选择低延迟音频设备
- 关闭不必要的音频增强功能
- 使用有线连接而非蓝牙

#### 3. 系统优化

- 关闭不必要的后台程序
- 提高程序进程优先级
- 使用高性能电源计划
- 确保充足的CPU和内存资源

#### 4. 震动映射优化

```python
# 在GUI中调整这些参数以获得更快响应
- 平滑度: 降低到0.3-0.5 (原0.7)
- 攻击时间: 减小到0.05秒 (原0.1秒)  
- 衰减时间: 减小到0.2秒 (原0.5秒)
```

## 性能监控

### FPS指标含义

- **>100 FPS**: 优秀，延迟<10ms
- **60-100 FPS**: 良好，延迟10-16ms
- **30-60 FPS**: 可接受，延迟16-33ms
- **<30 FPS**: 需要优化

### 性能问题排查

#### 低FPS原因:

1. **音频设备问题**:
   ```bash
   # 列出设备并选择最佳设备
   python main.py --list-devices
   python main.py --device-id X
   ```

2. **CPU不足**:
   - 减小块大小到更大值 (1024->2048)
   - 关闭图表显示 (使用命令行模式)
   - 降低GUI更新频率

3. **内存不足**:
   - 程序自动使用较小的缓冲区
   - 关闭其他应用程序

#### 高延迟原因:

1. **音频驱动延迟**: 使用ASIO驱动
2. **系统音频延迟**: 调整系统音频设置
3. **网络震动**: 检查手柄连接（有线优于无线）

## 实时性能调优

### 预设模式对性能的影响

- **intense**: 响应最快，但震动强度大
- **balanced**: 平衡响应速度和平滑度
- **gentle**: 最平滑，但响应略慢

### 动态调整建议

1. **音乐应用**: 使用balanced或gentle
2. **游戏应用**: 使用intense模式
3. **录音监控**: 使用最小块大小和intense模式

## 故障排除

### 延迟过高 (>50ms)

1. 检查音频设备延迟
2. 减小chunk-size参数  
3. 使用intense预设
4. 检查系统性能

### 震动断断续续

1. 增大chunk-size参数
2. 检查手柄电量和连接
3. 降低GUI更新频率
4. 使用gentle预设

### CPU使用过高

1. 增大chunk-size到2048或4096
2. 使用命令行模式: `--no-gui`
3. 降低采样率: `--sample-rate 22050`
4. 减少图表更新频率

## 硬件建议

### 推荐配置
- CPU: 4核心以上，3GHz+
- 内存: 8GB+
- 音频: 专业音频接口或低延迟声卡
- 手柄: 有线Xbox手柄

### 最低配置
- CPU: 双核2GHz
- 内存: 4GB
- 音频: 板载声卡
- 手柄: 无线Xbox手柄

注意：在低配置系统上，建议使用较大的块大小(2048-4096)和命令行模式以确保稳定性。
